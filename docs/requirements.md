# 需求确认记录

本文档记录项目启动前与用户逐条确认的决策，是开发与验收的依据。

## 产品目标

- 支持平台：Android（原生 App）；Windows / macOS / iOS（通过 Web 浏览器）
- 玩法：你画我猜
- UI 风格：新野兽派（Neo-Brutalist），规范见根目录 `新野兽派.txt`
- UX 要求：移动端仅常显画布、剩余时间、提示词，其余信息折叠隐藏；桌面端全部展示；必须有音效提示

## 已确认决策

1. **Android 客户端**：Kotlin + Jetpack Compose；先完成 Web 端，再开发 Android 端。
2. **Web 前端**：React + TypeScript + Vite + Tailwind CSS。
3. **实时通信**：统一使用 ASP.NET Core SignalR（WebSocket）。
4. **游戏模式**：
   - 画师顺序固定（按加入房间的顺序轮转）。
   - 抢占模式：本轮只要有 1 人答对，立即结束本轮并进入下一位画师。
   - 递减模式：每轮初始满分，随剩余时间减少而递减，越早答对得分越高；多人可先后答对。
5. **计分与持久化**：服务端只负责通讯，不落库；每局数据独立，历史战绩由各客户端本地保存。EF Core + SQLite 仅作为后续里程碑的工程预留。
6. **词库**：客户端保存词库（TXT，一行一个词，`/` 分隔别名）；房主从自己客户端内存导入；服务端不持久化，仅在本房间内存中分发；提示词（如字数）由画师自行发送。
7. **投票踢人**：等待界面和对局中都可发起；超过半数且至少 2 票通过；房主不可被踢；被踢者本局不能重进。无额外拉黑需求。
8. **房主设置**：词库、总轮数、每轮时间，另加客户端音效开关。
9. **聊天**：猜词输入即聊天（消息公屏显示，完全匹配答案才判对），MVP 不做独立聊天面板。
10. **音效**：Web Audio API 合成音效（倒计时、答对、答错、抢答、回合结束、点击）；Android 端后续使用 ToneGenerator 或合成音效。
11. **部署**：同时支持 Docker 与非 Docker；预计同时在线约 10 人。
12. **Git 流程**：main 为默认分支，功能分支 `feature/*`，合并验证后推送；首次提交因远端历史不同步使用 force push；MIT License。
13. **交付顺序**：先交付可玩的 Web MVP（建房/加入/画画/猜词/计分/房主设置/投票踢人/词库导入），Android 端为第二阶段。

## 已知限制（MVP）

- 房间数据仅存于服务端内存，进程重启即丢失。
- 断线即视为离开房间；重进房间会作为新玩家加入（历史分保留在客户端本地统计中）。
- 对局中玩家少于 2 人时，游戏回到等待界面。
